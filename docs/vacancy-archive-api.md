# Архив вакансий проекта — API

База: dev 1c424ff. Дизайн и ручные действия согласованы 21.10.2026.

- PATCH /vacancies/{id}/: is_active=false закрывает набор, отклоняет ожидающие отклики и ставит email-уведомления после commit. Повторное закрытие не меняет дату и не дублирует письма.
- PATCH с is_active=true: возобновление требует опубликованного публичного проекта, не меняет прежние решения.
- DELETE /vacancies/{id}/: наличие любого отклика запрещает удаление, включая архив. Ответ 400 содержит code=vacancy_has_responses и detail.
- Поле total_response_count readonly и включает всю историю. response_count продолжает считать ожидающие решения отклики.
- Руководитель и администратор проверяются после блокировок Project → Vacancy. Порядок совместим с операциями над откликами.
- В публичном представлении проекта закрытые вакансии скрыты; менеджер видит обе группы.
- PATCH/PUT валидируются до изменений. Invalid skills не удаляют прежние навыки; PUT без is_active не отклоняет отклики.
- Архив остается закрытым при повторной публикации проекта до ручного возврата. Дата закрытия и история не меняются. Принятие кандидата также отменяет автоматическое возобновление.
- Только новые вакансии черновика и активные вакансии, временно скрытые при переводе проекта в черновик, возобновляются вместе с проектом. Создание блокирует Project, чтобы не пропустить одновременную публикацию.

Новых endpoint нет. API с миграцией `vacancy.0011_vacancy_resume_on_publish` нужно внедрять до связанного Angular PR.
Внутренний `resume_on_publish` не входит в API. Значение по умолчанию false сохраняет все старые закрытые записи
в архиве, включая закрытые вакансии старых черновиков: причина их закрытия ранее не сохранялась,
поэтому автоматический возврат для них не предполагается. Статусы и даты миграция не переписывает.
После публикации руководитель может вернуть нужные старые вакансии вручную.

## Проверено

PostgreSQL 18.1, Python 3.11.15 / Django 4.2.11, отдельная локальная test database.
`manage.py test vacancy.tests projects.tests.test_project_signals projects.tests.test_program_project_detail_access --noinput --keepdb` — 119 tests passed.
`manage.py check --tag models`, `manage.py makemigrations --check --dry-run`, Black измененных файлов — exit 0.
Тесты покрывают историю, pending-only notifications, повтор, возврат, permissions, прямой DELETE,
атомарность, публичное представление, совместимость счетчиков, повторную публикацию, создание в черновике,
принятие кандидата во временно скрытую вакансию и upgrade миграции на существующих записях.
Регрессионные проверки количества SQL-запросов проходят.

Ревью проверило блокировки и повторную проверку владельца, сохранение истории и отказ прямому API,
совместимость payload и readonly fields, callback после commit и сохранение старых статусов/дат в миграции.
Реальная доставка email и deployed dev не проверены. Полный suite запускает CI PR.
