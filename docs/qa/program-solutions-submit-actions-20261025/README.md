# QA01: первая сдача организатором

Проверен API существующего привилегированного сценария: организатор впервые сдает готовое решение после дедлайна через signed preview/confirmation. Обычная сдача капитана, уже сданный snapshot и project actions сохраняют правила. [Spec и audit SADM01–SADM10](../../product/program-solutions-be08-submit-actions.md). Общий первый выпуск не завершен.

[Final HTTP evidence](http-evidence.json): 42 настоящих HTTP/JWT запроса с проверкой request/response C00 1.14.0, обе формы, программы 19/20, решения 26/28 и сданные anchors 27/29. Использованы отдельный локальный API 8877, PostgreSQL 18/main procollab_ci, locmem mail; только новые синтетические fixtures. После закрытия срока и выключения creation flag капитан получает submission_closed, manager проходит preview → confirmation. Устаревшее подтверждение после реального PATCH и replay получают solution_action_conflict. Mixed action дает changed=1/already=1 и сохраняет anchor. Snapshot включает принятый состав, число 0, false и сохраненные поля; pending не становится членством. All-submitted preview дает null token. Последующий PATCH сданного решения отклоняется.

Preview не меняет domain data. Hash прежних строк 11 выбранных моделей совпал до/после финального прогона; Project не создавался. Пользователи и file owner использованы только из прежних синтетических QA аккаунтов. Presentation field явно настроен optional; капитан прикладывает ранее зарегистрированный собственный проверенный PDF. Binary upload/CDN delivery этим прогоном не повторяются. JWT и подписанные action tokens не включены в evidence; SHA256 ответов записан после schema validation.

Промежуточный HTTP прогон на программах 17/18 также прошел 42 checks. После review найден gap между fingerprint файла и его финальной блокировкой; file locks перенесены до проверки состояния. Локальный worker остановлен по проверенным PID/command line и запущен на новом source, final HTTP повторен на свежих 19/20; прежние работы не удалялись и не перезаписывались. Оба ранних creation flags выключены; final 19/20 выключают создание до manager submit. Фикстуры сохраняются для проверки.

Checked by tests: final 325 PostgreSQL tests решения/оценивания/legacy actions PASS, из них 17 новых. Confirm×confirm и confirm×captain PATCH наблюдают настоящие wait paths обоих PostgreSQL worker до снятия program lock. Final `npm run test:ci` — 2793 tests/479 files + strict C00 types PASS; 30 новых wire tests используют настоящий CamelcaseInterceptor и API adapter. Ранний unused @ts-expect-error был исправлен по месту TS property error; итоговый полный прогон прошел. Development build/scoped ESLint, Black/Flake8/Django/migration consistency/C00 PASS.

[Source provenance](source-provenance.json) фиксирует SHA256 runtime файлов, contract files и helper. Это API проверка; manager UI, browser flow D02, production, большой объем выборки и новый Linux CI не подменяются локальными результатами.
