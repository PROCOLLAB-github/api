# Возврат стандартной обложки legacy-проекта

База DEV: `8ed5670d2123dd1f1b53668567ad60bde8641bcc`.
Задача относится к Angular и `Project`; модели и контракты React не изменены.

## Причина

Пользователь подтвердил на DEV попытку удалить стандартную обложку через
`DELETE /files/?link=...` и ответ 403: её `UserFile` принадлежит другому пользователю.
Второй конфликт — физическое удаление пользовательской обложки очищает обязательный
Angular-control. Глобальное удаление файлов и `Project.save()` не меняются.
На живом DEV автор этой правки удаление не выполнял. Сохранность общего файла и 403
для чужого `UserFile` дополнительно проверены локальными API-тестами.

## Контракт

`POST /projects/{project_id}/reset-cover/`, тело `{}`. ID относится к `Project`,
а не `PartnerProgramProject`.

Успех 200:

```json
{
  "cover_image_address": "https://cdn.example/default.png",
  "is_default_cover": true
}
```

Если доступных записей с непустой ссылкой `DefaultProjectCover.image` нет:

```json
{
  "code": "default_cover_unavailable",
  "detail": "Стандартная обложка временно недоступна."
}
```

Статус 409; проект и прежний файл сохраняются. Проверка доступности означает
наличие ссылки в БД: отдельный сетевой HEAD в CDN не выполняется.
Уже стандартная обложка возвращается без переназначения и удаления.
Сокращённые списки проектов сохраняют прежний контракт.

`GET /projects/{id}/` и ответы изменения проекта содержат read-only
`is_default_cover`. Источник — точное совпадение URL с `DefaultProjectCover.image_id`.
Сериализатор загружает набор ссылок один раз на экземпляр, в том числе при `many=True`.
Это не глобальный кеш; после PUT проверяется фактическое значение, включая fallback
существующего `Project.save()`.

## Права и порядок записи

Команда использует непосредственно `ProjectDetail.permission_classes`:
`ProjectVisibilityPermission`, `HasInvolvementInProjectOrReadOnly`,
`TimingAfterEndsProgramPermission`. Object permissions проверяются на заблокированном
`select_for_update()` проекте внутри транзакции.

- Лидер сохраняет прежние права.
- Collaborator/invite могут менять только доступный черновик по прежним правилам.
- Менеджер, эксперт или администратор не получают право записи только из-за роли.
- Сохраняется временной запрет редактирования после завершения программы.

Сначала записываются новая обложка и время изменения проекта. Только после коммита
`on_commit` запускает best-effort очистку. При откате транзакции очистки нет.

| Прежний файл | Поведение |
| --- | --- |
| Стандартная обложка | Идемпотентный ответ, без удаления |
| Собственный свободный `UserFile` | После коммита — CDN DELETE, затем удаление записи |
| Чужой `UserFile` | Сброс разрешён по правам проекта; файл сохраняется |
| Запись файла отсутствует | Сброс успешен, CDN не вызывается |
| Системный аватар или файл, используемый другим проектом | Очистка пропускается |
| CDN возвращает 404 | Очистка считается идемпотентной |
| CDN/network/БД очистки выбрасывает ошибку | Новая обложка сохраняется, ответ остаётся 200, запись файла остаётся при сбое CDN |

Предупреждение очистки не содержит URL, пользователя, HTTP body или текста исключения.
Автоматическая очередь повторной очистки не добавлялась. Неудачная очистка может
оставить неиспользуемый файл; она не возвращает проекту удалённую обложку.
Общие права `/files/` и правила публикации/сдачи проекта не изменены.

## Реальная локальная интеграция с Angular

Отдельная БД `procollab_cover_reset_20260917` создана из предыдущего синтетического
локального стенда. Никаких DEV/PROD данных. Работали настоящий Angular, Django,
JWT, `Project`, `UserFile`, связи программы и права доступа. Только внешний CDN
заменён локальным файловым транспортом; его сбой задавался явно.

| Сценарий | Результат |
| --- | --- |
| A: стандартная обложка | В редакторе нет удаления/сброса; DELETE отсутствует |
| B: upload → save → reopen | POST файла 201, PUT реального проекта 200; GET возвращает пользовательский URL и false |
| C: reset → GET → reopen | POST 200; фактическая стандартная ссылка и true; прежний собственный файл удалён после смены ссылки |
| D: чужой файл при законном редактировании | POST 200; стандартная ссылка; `UserFile` другого владельца сохранён |
| E: нет DefaultProjectCover | POST 409; понятная ошибка UI; GET сохраняет прежний URL и false |
| F: отказ CDN после переключения | POST 200; GET возвращает стандартную ссылку и true; прежний файл сохранён, предупреждение записано |

В браузерной цепочке A–F не было `DELETE /files/`, `/projects/NaN/`, `/0/`, `/null/`
и ответов 5xx. Кейс связи 73 с программой 21 сохранился при сохранении проекта 31.
Скриншоты и обезличенный сетевой протокол находятся в Angular Draft PR этой задачи.
