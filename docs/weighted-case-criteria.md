# Процентные веса критериев кейса

Согласовано 11 ноября 2026: пользователь выбрал проценты с общей суммой 100%
и итог кейса 0–100. Эта задача не включает квиз и смешанный рейтинг квиза/кейса.

## Исходное поведение и границы

API base: `b4575a0770c0515a8099cd3920416a7cbcf953bf`, Angular base:
`936dd7e1043f07c4a25dcd819ae7d5523644724f`, ветки от dev. Работа выполняется
отдельно от white label PR и опубликованного пилота; серверы не изменяются.

`Criteria` сейчас содержит тип и шкалу, без веса. Общая
`project_rates/evaluation_math.py:evaluation_totals` суммирует числовые критерии
полной оценки и усредняет суммы экспертов. Ее используют результаты Project и
ProgramSolution. Результаты и XLSX используют общий snapshot, но XLSX также
содержит собственные формулы SUM/AVERAGEIF. Число полных оценок для допуска в
рейтинг, места при равенстве, сроки и object permissions уже определены кодом.
`criteria_policy` фиксирует критерии после первой сохраненной оценки.

Организатор редактирует критерии в существующем разделе управления и Django
admin. Эксперт выставляет исходные баллы; участник не задает веса. Права остаются
на сервере и ограничены той же программой. Angular получает веса из API.

## Правила расчета

- Существующие программы сохраняют режим `legacy`: результаты не пересчитываются.
- Режим `weighted_percent` выбирается организатором до первой сохраненной оценки.
- Каждый числовой критерий имеет вес больше 0 и не больше 100%, до двух знаков
  после запятой. Общая сумма числовых весов должна быть ровно 100%.
- Шкала каждого взвешенного критерия конечна, максимум строго больше минимума.
  Нормализованный вклад: `(оценка − минимум) / (максимум − минимум) × вес`.
- Минимум шкалы дает нулевой вклад, максимум — полный вес. Например, 8 из 10
  при шкале 0–10 и весе 40% дают 32 балла из 40.
- Комментарии и «да/нет» не имеют числового веса. Их прежние правила заполнения
  и завершенности не меняются.
- Итог эксперта — сумма вкладов. Итог команды — среднее полных оценок экспертов.
  Все эксперты равноправны; неполная оценка не превращается в ноль.
- Расчет выполняется Decimal без промежуточного округления вкладов. Финальный
  балл округляется до двух знаков HALF_UP; действующие правила мест сохраняются.
- Сумма весов, шкалы, режим и веса блокируются после первой сохраненной оценки,
  включая частичную. Проверка и сохранение используют общий program lock.
- В XLSX исходные баллы, веса и итог должны воспроизводить расчет API.

## Контракт и совместимость

В `GET/PUT /programs/:id/management/criteria/` добавляются `scoring_mode`
(`legacy|weighted_percent`) и nullable `weight_percent` у критерия. Старый PUT
без новых полей сохраняет текущий режим и веса существующих критериев. В новом
режиме сохранение неполного/невалидного набора возвращает 400 атомарно.
Существующие 401/403/404 и 409 `stale_criteria|criteria_locked` сохраняются.
Режим и веса входят в revision: устаревшая экспертная форма не пишет оценки
по измененным правилам. Payload исходных экспертных баллов сохраняется.

Результаты Project и ProgramSolution добавляют режим, веса и вклады, сохраняя
исходные averages. Для нового режима maximum=100. Общая формула используется
обоими контурами; сущности и их права не объединяются. Отдельный React
Submission/Evaluation API не меняется.

Нужны две добавочные миграции: режим в PartnerProgram с default legacy и nullable
Decimal-вес в Criteria. Старые записи остаются без весов. Backend выкладывается
перед Angular; миграции и установка на pilot выполняются отдельным контролируемым
этапом после verification. Автоматического изменения dev/prod нет.

## UI и админка

Расширяется существующая форма критериев: выбор способа расчета, поле «Вес, %»
у числового критерия и сумма весов с ошибкой при отклонении от 100%. Строка
критерия и форма эксперта показывают вес, результаты — формулу и вклад. Сохраняются
текущие карточки, модальное окно, Mont, controls и responsive layout; нового
экрана или изменения структуры навигации нет. Это ограниченное расширение
существующих полей, без отдельного нового визуального дизайна.

В Django admin требуется эквивалентное атомарное редактирование всего набора
через тот же service, а не обход проверки суммы отдельными записями.

## Acceptance criteria

- W01: legacy программа с прежними оценками сохраняет прежние баллы, максимум,
  места и XLSX. Проверка регрессионными тестами обеих моделей результатов.
- W02: manager своей программы сохраняет веса 40/35/25 и режим weighted_percent;
  повторный GET возвращает те же числа. Проверка API и БД PostgreSQL.
- W03: неверная сумма, ноль/отрицательное/NaN/Infinity, больше двух знаков,
  нечисловой взвешенный критерий и вырожденная шкала отклоняются без частичных
  изменений. Проверка API/model/admin tests.
- W04: чужая программа/роль/гость не могут изменить веса; старый revision и первая
  сохраненная оценка дают прежний 409. Проверка прямых HTTP-запросов и гонки.
- W05: на разных шкалах вклад нормализуется, максимум=100, минимум=0; неполные
  оценки не входят в среднее, эксперты равноправны. Проверка Decimal примерами.
- W06: после первой оценки режим/веса нельзя изменить через API, model и admin;
  экспертный POST проверяет актуальный revision. Проверка PostgreSQL tests.
- W07: Project и ProgramSolution с одинаковыми данными получают одинаковые
  итоги, вклады и места; экспортные формулы воспроизводят результат.
- W08: Angular позволяет настроить веса, показывает их сумму и ошибки, сохраняет
  черновик при 409 и блокирует форму после фиксации. Старый API без новых ключей
  работает как legacy. Проверка component/adapter tests.
- W09: эксперт видит вес без ручного умножения; результаты показывают корректную
  формулу/максимум. Проверка тестами и браузером desktop/mobile, клавиатурой.
- W10: миграции применяются к отдельной тестовой PostgreSQL; проверки/build и
  итоговый review подтверждены до PR. Реальные серверы не затрагиваются.

## Порядок реализации

Backend-first: models/migrations → общий расчет и policy → атомарная настройка
API/admin → результаты/XLSX → API/locking/regression tests. Затем Angular
domain/adapter → существующие формы/результаты → tests/build/browser → review
обоих PR. По завершении фиксируются фактические проверки и ограничения.

## Проверка реализации 11 ноября 2026

Checked by source: общий расчет используется результатами Project и ProgramSolution,
а API организатора и пакетный редактор Django admin вызывают один service. Права
организатора прежние: manager своей программы или staff; Django admin дополнительно
проверяет модельные view/change permissions. Веса и режим входят в revision.
Удаление ограничено проверенными ID; после program lock повторно проверяется
принадлежность изменяемого критерия и критерия сохраняемой оценки.

Checked by tests: на отдельном PostgreSQL прошли 235 тестов `project_rates`,
`partner_programs.tests.test_management_criteria_api`, `test_management_results_api`,
`test_management_api`. Включены миграция туда/обратно с прежними оценками,
паритет Project/ProgramSolution, гонка первой оценки и изменения весов, удаление
замененного набора и перенос критерия до program lock. Негативные роли отдельно
перепроверены прямыми HTTP-запросами. Black и Python lint E/F/W прошли;
`makemigrations --check --dry-run` не обнаружил изменений.

Checked by build: Angular production build и 57 тестов в семи файлах прошли,
включая adapters, общий expert form, обе модели результатов, criteria editor и
solution evaluation contract. C00 1.22.0: 156 schemas, 59 operations, 307 scenarios;
валидатор OpenAPI и TypeScript contract check прошли. Добавления схем и примеров
совпадают в двух repos; прежнее различие описаний published-solutions GET вне
этой задачи сохранено. Проверки форматирования и ESLint ограничены измененными
файлами; общерепозиторные автоисправления не запускались.

Checked in browser: production Angular build с настоящим изолированным Django API,
синтетическими аккаунтами и заблокированными внешними сервисами. Организатор
сохранил 40/35/25 через форму; до распределения 100% сохранение недоступно.
Эксперт через форму сохранил 8/7/6: 71,5 балла. Второй эксперт отправил 10/8/8
через обычный API: 88 баллов. Рейтинг показал 79,75 из 100 и первое место;
формула показала вклады 36 / 26,25 / 17,5. Первая оценка заблокировала настройки.
Desktop 1440 px и mobile 390 px проверены; форма и объяснение без горизонтального
скролла. Enter открывает объяснение, Escape закрывает; числовое поле preview
сохраняет доступное имя критерия. Ошибок страницы не было. Проверены текущие
Mont/components/layout; новых CSS, декоративных анимаций и UI-библиотек нет.

Скачанный через API XLSX пересчитан LibreOffice: итоги экспертов 71,5 и 88,
рейтинг 79,75, веса 40/35/25. Это проверка вычисленных значений, а не только текста
