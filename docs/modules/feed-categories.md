# Контракт категорий ленты

`GET /feed/?type=all_news&limit=6&offset=0` сохраняет стандартную
пагинацию `count`, `next`, `previous`, `results` и дополнительно возвращает
`counts` — количество доступных пользователю записей во всей ленте, независимо
от текущего фильтра и страницы:

```json
{
  "counts": {
    "all": 4,
    "all_news": 2,
    "project": 2,
    "project_news": 1,
    "new_project": 1,
    "vacancy": 1,
    "news": 1,
    "partnerprogram": 0,
    "education": 0
  }
}
```

- `all_news` — публикации проектов и пользователей.
- `project_news` — только публикации проектов.
- `news` — только публикации пользователей.
- `vacancy` — активные вакансии.
- `new_project` — записи о новых проектах.

Черновики, закрытые проекты и неактивные вакансии не учитываются. Новости программ
и образование пока не включены в этот endpoint, поэтому их счётчики равны нулю.
Для совместимости `project` по-прежнему включает публикации и записи о новых
проектах, а `all` учитывает все видимые записи, включая вакансии. Фильтры можно
объединить через `|`.

Каждый элемент `results` теперь содержит `published_at` — дату публикации
записи ленты. Поле есть и у карточек новостей, и у вакансий, и у новых проектов.
При одинаковой дате сортировка дополнительно использует первичный ключ (`pk`)
по убыванию, чтобы последовательность страниц была определённой.
