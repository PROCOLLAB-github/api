## API

Все управляющие пути: `/programs/{id}/management/certificates/`, private/no-store.
JSON использует snake_case; штатный Angular API interceptor преобразует регистр.

- GET /: `{revision,draft,assets,eligible_counts,batch}`. Начальный шаблон без демоданных.
- PUT /: `{revision,draft}`. Конфликт ревизии 409, невалидные поля 400.
- POST assets/: multipart `file`, `kind=background|signature`; проверка реального
  содержимого PNG/JPEG, до 10 MB и 20 MP; подпись PNG. GET assets/{asset_id}/.
- POST preview/: `{revision,long_name?: boolean}` → PDF с тем же примером имени,
  что в редакторе; `long_name` выбирает длинное ФИО. Без выдачи участнику.
- POST test/: `{revision}` → письмо с пробным PDF только текущему организатору.
- POST activate/: `{revision}` → неизменяемый снимок шаблона и рассылки;
  `timing=manual` запускает сейчас, `scheduled` требует дату не ранее окончания.
- POST pause/ и resume/: останавливают/возобновляют очередь текущего запуска.
- GET deliveries/: `status=all|sent|failed`, `search`, `limit` (до100), `offset`;
  `{count,results,summary}`; PDF и отправка имеют независимые состояния.
- POST retry/: `{ids?: UUID[]}`; только ошибки, повторно используется готовый PDF.
- GET deliveries/{certificate_id}/pdf/: PDF, GET archive/: ZIP готовых PDF
  с теми же фильтрами. Ошибки без готового PDF остаются в журнале.
- GET `/programs/{id}/certificates/me/`: собственные выданные сертификаты.
- GET `/programs/{id}/certificates/download/{token}/`: PDF по секретной ссылке
  из письма (случайный UUID, без раскрытия списка участников).

Celery beat раз в минуту подбирает запуски и сохраняемую очередь. Уникальный
ключ program/user исключает повторную выдачу. Сохранение настроек само по себе
не меняет выданные документы. Их обновление требует явного действия менеджера.
Отправка с неопределенным результатом после падения worker требует ручного
повтора, чтобы автоматически не дублировать письма. `sent` означает принятие
почтовым провайдером, а не доказательство попадания во входящие.

Активы и PDF хранятся приватно в БД: не требуют нового публичного CDN или
непостоянного диска контейнера, сохраняют прозрачность подписи. Это увеличивает
объем БД; для больших объемов можно заменить содержимое приватным object storage.
PDF использует уже имеющиеся WeasyPrint и Mont. Загрузчик PDF запрещает сеть
и произвольные файлы. Поля письма поддерживают только перечисленные подстановки.

## Готовый фон и видимость элементов

В `draft` добавлен необязательный `hidden_elements`: список ключей `title`,
`subtitle`, `program`, `date`, `number`, `director`, `position`, `signature`.
Имя обязательно; `name`, неизвестные ключи, повторы и null отклоняются с 400.
Все девять блоков `layout` сохраняются, включая геометрию скрытых элементов.
GET/PUT возвращают нормализованный список; права и revision/409 не менялись.

Новые настройки содержат только имя по центру A4. Существующие JSON без нового
поля сохраняют видимость и координаты; `show_text=false` по-прежнему скрывает
заголовок и подзаголовок. PUT старого клиента без `hidden_elements` сохраняет
текущую видимость, а явное переключение legacy `show_text` меняет эти два блока.
Новый Angular редактор нормализует legacy-флаг и управляет каждым блоком отдельно.

Готовый PNG/JPG можно использовать целиком, оставив поверх только имя.
Preview и новые снимки выдачи используют одинаковую видимость; текст Mont
переносится и подгоняется по реальной ширине и высоте области. Ранее выданные
PDF не изменяются, миграция БД не требуется. Порядок внедрения: API, затем
парный Angular PR; обновленные клиенты требуют поддержки нового поля сервером.

## Приемка

1. Новая вкладка доступна менеджеру, чужая программа возвращает 403.
2. Фон/подпись загружаются, элементы перетаскиваются/масштабируются без X/Y-полей.
3. PDF A4 альбомный, кириллица и длинные имена корректны, есть пробный PDF.
4. Два режима получателей, дедупликация регистраций и команд.
5. Выдача по расписанию или вручную, подтверждение и пауза очереди.
6. Фильтры Все/Отправлено/Ошибки с серверным поиском и пагинацией.
7. Повтор только ошибок, тот же PDF, отправленные письма не дублируются.
8. Свой PDF в программе и ссылка в сервисном письме; защита чужих документов.

## Ориентация А4

`draft.orientation` принимает `landscape` (297 × 210 мм) или `portrait`
(210 × 297 мм). Новые и старые шаблоны без этого поля используют `landscape`.
При сохранении старым клиентом без поля API сохраняет предыдущую ориентацию.
Неизвестные значения отклоняются без изменения ревизии. Ориентация входит в
снимок выдачи; preview и генерация PDF используют его физические размеры,
включая подгонку текста. Фон вписывается целиком без обрезки; вертикальные
изображения сохраняют разрешение до 2480 × 3508. Ранее сформированные PDF
не пересоздаются. Миграция базы не требуется.

## Шрифты элементов

`layout.<element>.font_family`: `mont`, `pt-serif` или `lobster`. Выбор хранится
отдельно для каждого элемента и входит в снимок выдачи. Старые шаблоны без поля
используют Mont. Старый клиент, опустивший поле, сохраняет предыдущий выбор
конкретного элемента; неизвестные семейства и произвольные URL отклоняются.
Pillow и PDF используют одни и те же локальные TTF, выбранный шрифт встраивается
в PDF. PT Serif использует 400/700, Mont 400/600, Lobster единственный 400 без
синтетического полужирного начертания. Шрифт изображения подписи не применяется.
Миграция и обновление ранее выданных PDF не требуются. Источники и лицензии:
`assets/certificates/fonts/README.md`.

## Управление выданными сертификатами

- Журнал поддерживает `unsent` и возвращает `outdated` у строки, счетчики
  `unsent`/`outdated`. Сравнивается визуальный шаблон, без настроек письма и расписания.
- `POST selection/`: `{revision,action,ids}` либо
  `{revision,action,all_matching:true,status,search,excluded_ids}`. Выбор всех
  охватывает весь фильтр, а не страницу. ID другой программы, конфликт ревизии
  и строки в обработке отклоняются до изменений.
- `action=send` отправляет выбранным с текущим шаблоном, пропуская `sent`.
  `refresh` пересоздает PDF без писем; `retry` сохраняет прежний способ доставки
  каждой строки, включая режим только на платформе. Ответ: `{count,skipped}`.
- Ручные задания используют отдельные неизменяемые снимки с `manual_action` и
  не подменяют управление автоматическим запуском. Обрабатываются штатным outbox.
- `POST deliveries/{id}/pdf/` с `{revision}` применяет текущий шаблон при
  необходимости, сохраняет PDF и возвращает его. `POST archive/` с ревизией
  и тем же выбором делает это для ZIP. Секретная ссылка участника сохраняется.
  Новая версия получает статус `ready`, письмо само не отправляется.
- Старые GET download/archive и retry остаются совместимыми. Повторное скачивание
  текущего PDF не пересоздает файл. Ошибка генерации откатывает изменения транзакции.

Отправление проверяется отдельно от готовности PDF: `ready` означает доступность
на платформе, не письмо.

## Замена PDF без разрыва ссылки

`ProgramCertificate.rendered_batch` указывает на снимок фактически сохраненного
PDF; `batch` — на текущее задание. Массовое обновление сохраняет прежний файл и
его снимок, пока worker не создаст новую версию. PDF и `rendered_batch` меняются
одним UPDATE. При ошибке старая ссылка продолжает возвращать прежний PDF, а
журнал показывает `pdf_error` и расхождение с текущим шаблоном. Повтор использует
нужный снимок, а успешно созданный PDF не генерируется заново при почтовой ошибке.

Нужна миграция `0031_programcertificate_rendered_batch`: она добавляет nullable FK
и запоминает существующий batch у строк с PDF. Байты, токены, статусы, даты и
письма не меняются. Старые записи без provenance имеют совместимый fallback;
перед изменением задания их исходный снимок запоминается. Сначала миграция/API
и worker, затем frontend с распознаванием ошибки обновления.
