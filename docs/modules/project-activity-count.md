# Статистика активности пользователя по проектам

Источник данных — legacy endpoint `GET /projects/count/`. Он возвращает
совместимые с прежним контрактом поля `all` и `my`, а также три показателя
жизненного цикла проектов пользователя:

```json
{
  "all": 123,
  "my": 7,
  "my_leader": 4,
  "my_in_program": 2,
  "my_submitted": 1
}
```

- `my` — число уникальных legacy `Project`, где пользователь является
  лидером или участником `Collaborator`.
- `my_leader` — число проектов, где пользователь указан в `Project.leader`.
- `my_in_program` — число проектов пользователя с канонической связью с
  программой, включая черновики и уже сданные проекты.
- `my_submitted` — число проектов пользователя, у которых каноническая связь
  помечена как сданная. Сданный проект учитывается независимо от `draft`,
  поскольку состояние «Сдано» имеет приоритет над «Черновиком».

`my_submitted` всегда не больше `my_in_program`: сданные проекты составляют
подмножество проектов, привязанных к программе.

Канонической считается запись `PartnerProgramProject` с минимальным `pk`
для проекта. Это совпадает с правилом, которое используется legacy-карточками
и detail проекта при наличии нескольких связей с программами.

Расчёт выполняется на backend одним агрегирующим SQL-запросом с условными
`Count` и `Subquery`. Его нельзя строить по данным dashboard: Angular
загружает там только первые 16 проектов, поэтому клиентский расчёт давал бы
неполную статистику. Проверка на PostgreSQL подтверждает один запрос как для
одного, так и для 31 проекта.

Расчёт не обращается к React-домену и не меняет права, submit-логику или модели
`Application`, `Team`, `Submission`, `Evaluation` и
`SubmissionExpertAssignment`.
