# BE06: сдача решения и неизменяемый снимок

POST submit принимает обе ожидаемые ревизии и выполняет однократную сдачу под общими блокировками программы, решения, определений, принятого состава и файлов. Повторяются проверки капитана, финального состояния, режима, версий, конкурсности, срока, регистрации/exclusivity состава, минимума/максимума по принятым участникам, кейса, обязательности, типов, ограничений и материалов. После возможной проверки прежнего файла срок повторяется по времени, которое записывается как submitted_at. Включенная граница дедлайна сохранена.

Успех одной транзакцией пишет status, submitted_at, version и JSON snapshot с названием, капитаном, принятым составом, определениями/ревизией формы и ответами. Pending приглашения не входят в состав снимка. Сданный GET использует снимок; новые подписи, порядок, required и границы программы не делают ранее сданную работу неготовой. Readiness черновика возвращает стабильные ID и причины состава/полей/материалов, can_submit вычисляется из роли и серверного состояния. Неконкурсная программа остается сценарием сохранения без сдачи.

Все команды API закрывают изменение ответов и состава после сдачи; pending revoke/decline остаются допустимыми. Обычные model saves и collector deletion дополнительно защищают сданные записи и снимок, оставляя версию для служебных действий. Прямые SQL/QuerySet.update используются только как низкоуровневая операция обслуживания и не являются пользовательским способом редактирования. Штатный legacy submit не отправляет отдельного события/уведомления; новая команда не вводит новый эффект и не начисляет оценки.

Проверено по исходникам: прежние submit_program_project, team_policy, проверка сроков программы и согласованный C00. Проверено тестами: 110 сценариев решения на локальном PostgreSQL, включая 20 новых проверок сдачи. Гонки двух submit, PATCH/submit, accept/submit, remove/submit, формы/submit и удаления файла/submit дают допустимые состояния; повторная сдача, права, срок, пустой кейс, некорректные старые данные, rollback, snapshot и model guards проверены. Black/Flake8 и migration consistency прошли. Полный Linux CI нового commit проверяется отдельно; предшествующий BE05 82e1a81 прошел 1455 + 39 PostgreSQL-проверок.

Проверено в браузере на настоящих Django/PostgreSQL/JWT: обе формы, предварительный PATCH, ошибки состава/файла с переключением вкладки и фокусом, приглашение и принятие второго участника, отмена подтверждения, mobile 390 px, submit с версией из PATCH, GET сданного состояния, readonly участника и капитана, отзыв pending после сдачи, изменение организатором живой формы без изменения снимка. Upload использовал локальный storage adapter, остальные endpoints и модели реальные. Production и реальные программы не менялись.
