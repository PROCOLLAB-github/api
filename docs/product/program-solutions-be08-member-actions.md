# BE08B: исключение участника решения организатором

Решение пользователя от 25.10.2026 сохраняет административные исключения после сдачи и требует совместимости действующих Project-программ. C00 1.18.0 фиксирует отдельное исключение принятого участника. Удаление регистрации, снятие/архив заявки и капитан в рамках этих действий остаются следующим объемом BE08.

## Поведение и границы

Организатор своей программы и администратор получают POST `/programs/{program_id}/management/solutions/{solution_id}/members/remove/preview/` и `apply/`. Тело preview содержит `user_id`, подтверждение дополнительно требует `preview_token`. Неизвестные поля/query, bool/string/fractional/unsafe IDs и отсутствующий token отклоняются. Ответы и ошибки имеют `Cache-Control: private, no-store`.

Preview показывает выбранного Member, оставшийся состав, состояние сдачи, число отзываемых pending-приглашений и сохраненных оценок. Он не меняет данные. Капитан показан с `can_apply=False`, ошибкой `captain_cannot_be_removed` и null token; операция не оставляет заявку без капитана. Отсутствующий участник дает404. Капитан, участник, эксперт и посторонний организатор не получают привилегию. Legacy mode дает409 и сохраняет прежние Project endpoints.

Signed proof действует10 минут и связан с actor/program/solution/user. Apply заново проверяет права и состояние после блокировок program → solution → members → invitations. Fingerprint включает решение/snapshot/version, роли/состав, приглашения, ответы, назначения и полные значения оценок. Измененный или использованный proof дает409/solution_action_conflict без повторного удаления и второй ревизии. Срок сдачи, текущая настройка формы и creation-only flag не закрывают утвержденную административную операцию.

Подтверждение удаляет членство только выбранного пользователя в выбранном решении и отзывает его pending-приглашения. Регистрация программы остается. Обработанные accepted/declined приглашения сохраняются для истории; сами по себе они не дают доступ к материалам и не могут быть приняты повторно. Другие заявки и команды пользователя не меняются. После исключения участник перестает получать закрытые материалы через членство; независимые manager/expert/public права проверяются обычными правилами.

Материалы, ответы/UserFile, капитан, статус и время сдачи, оценки и назначения не меняются. Для сданного решения текущий snapshot меняет только `members`. Исключение может уменьшить состав ниже min_size, как прежнее административное действие; min_size продолжает проверяться при обычной первой сдаче. Неконкурсный черновик остается черновиком без искусственной сдачи.

Удаление членства использует обычный ORM delete и строго ограниченную внутреннюю ContextVar capability для одной строки `(solution_id, member_id, user_id)`. Она существует только на время подтвержденного удаления и сбрасывается в finally, в том числе при ошибке. Обычные model/queryset/admin/cascade удаления сданного состава по-прежнему защищены pre_delete. Смена snapshot выполняется отдельным привилегированным writer; обычное редактирование после сдачи остается закрыто.

## История и хранение

SolutionAdministrativeChange дополнен nullable case fields, `removed_member` и `revoked_invitation_ids`; constraint различает change_case/remove_member. Миграция0036 меняет только таблицу истории, не переносит Project и не переписывает существующие сдачи. Прежние записи смены кейса сохраняются.

Удаление членства, отзыв pending, новый snapshot/version и запись истории выполняются в одной транзакции. Ошибка журнала откатывает все изменения. История хранит исключенного Member и снимки до/после; для draft оба snapshot null, Member остается в событии. Новая ревизия увеличивает solution version ровно на1. История остается неизменяемой и доступна только организатору/администратору своей программы через существующие history list/detail; список поддерживает оба типа событий. Старая форма ответа change_case сохранена без дополнительных полей.

C00 1.18:136 схем,53 операции,250 независимых сценариев. Все230 прежних сценариев и51 прежняя операция сохранены. SolutionAdminChange — discriminated union по action; SolutionCaseAdminChange в точности сохраняет прежнюю схему case event. Остальные130 прежних схем не меняются. Негативные `invalid_request` проверяются как не соответствующие request schema; валидатор не ослабляет контракт ради400-примеров.

## Проверки

18 новых native PostgreSQL tests проверяют draft/submitted/noncompetitive, права/режим/ID/строгое тело/query, сохранность материалов/регистраций/оценок/назначений, потерю доступа исключенного, историю, rollback и frozen guards. Три observed-lock races проверяют confirm × confirm, confirm × submit и confirm × score; helper доказывает ожидание обоих PostgreSQL backend на блокировке программы. Эти18 входят в общий solution suite, не прибавляются к нему повторно.

Frontend API layer содержит generated union/DTO, port/repository/adapter и два use case;22 новых wire checks проверяют body/token/effects/errors/unsafe IDs через настоящий interceptor. Еще3 history wire checks покрывают member detail/draft и смешанный список. Новый organizer layout/routes/SCSS не добавлялся: D02 approval уже запрошен. Результаты полного регресса и настоящего локального HTTP зафиксированы в отдельном QA отчете.

## Откат

0036 применяется после0035 до нового backend/frontend. При остановке пилота сохраняются таблица истории, поля и записи; schema-down удалил бы доказательства административных изменений. Читатель истории должен понимать оба action. Creation-only flag ограничивает создание и не является выключателем административных команд; откат запуска не подменяется переключением storage mode. Полный rehearsal первого выпуска остается в REL01. Старые программы продолжают использовать Project; BE10 выполняется отдельно после выпуска и утверждения списка переноса.
