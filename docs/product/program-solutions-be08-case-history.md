# BE08A: смена кейса после сдачи и история

Пользователь согласовал административные исключения после сдачи с обязательным сохранением старых программ и проектов. Этот этап реализует смену кейса и хранение ее истории. Исключение участников, удаление регистрации, отвязка/архив заявки остаются следующим объемом [BE08](program-solutions-be08-admin-exceptions.md); новый интерфейс организатора зависит от D02 approval.

## Модель хранения

ProgramSolution продолжает владеть материалами, составом и текущим submission_snapshot. Явная привилегированная смена кейса обновляет кейс в текущем снимке и соответствующем ответе. Другие материалы, состав, капитан, status, submitted_at и оценки сохраняются. Обычные participant/model writers остаются frozen.

SolutionAdministrativeChange хранит actor/actor_name, before_version/after_version, точные старый/новый кейсы и case_field_id, IDs снятых назначений, число сохраненных оценок и полные before_snapshot/after_snapshot. До первой административной правки before_snapshot сохраняет исходную сдачу; следующие записи сохраняют последующие версии. У черновика оба snapshot=null: отдельная сдача не создается. Каждый подтвержденный case action увеличивает version на1 и создает одну запись истории в той же транзакции.

Миграция0035 создает только таблицу истории и ограничения уникальности/версий/парности снимков. Она не переносит Project, не переписывает старые решения и не меняет режим программ. История доступна для чтения, добавление/изменение/удаление через Django admin закрыты; model save существующей записи и удаление защищены. Связь с решением PROTECT сохраняет историю при попытке физического удаления. Архивирование вместо удаления — отдельный еще не реализованный этап. Бинарные файлы не копируются: снимки сохраняют прежние ссылки UserFile/CDN.

## C00 1.17

Прежние POST case/preview и case/apply имеют прежние request bodies. Preview дополнен is_submitted, removed_assignments_count и score_count. Для корректного сданного решения can_apply=True; подписанное подтверждение привязано на10 минут к actor/program/solution/точному case_name и состоянию. Тот же кейс не применяется повторно. Неожиданные оценки/назначения у draft по-прежнему блокируют команду.

Под program→solution→fields/answers/members locks повторяются права, storage mode, текущий вариант и fingerprint. Fingerprint включает snapshot/version/answers/members, полные значения оценок, назначения и case scopes. Изменение оценки без смены ее ID, изменение scope, конкурирующая сдача или другая правка делает прежнее подтверждение устаревшим. Replay и stale token дают409/solution_action_conflict. Ошибка записи истории откатывает ответ, snapshot, version и снятие назначений целиком.

Существующее правило management_project_actions перенесено без удаления оценок: снимается только несовместимое назначение эксперта, у которого нет сохраненных оценок решения. Оцененные назначения сохраняются. case_field_id относится к применяемому снимку; подписи и порядок прежней формы не заменяются текущими настройками при обычной смене кейса. Срок сдачи и creation-only flag не отключают это действие над существующим решением.

GET `/programs/{program_id}/management/solutions/{solution_id}/history/` возвращает count/offset/limit/results, новые записи первыми; limit1–100, default20, offset default0. GET `.../history/{change_id}/` возвращает change и before_snapshot/after_snapshot существующего SubmissionSnapshot DTO. История ограничена парой program/solution/change, доступна только organizer/admin своей программы и не требует актуальной настроенной формы. Неизвестные query запрещены; все ответы private/no-store. В ответах нет регистрационных данных или email. Обычные участники и эксперты не получают историю.

Добавлены3 схемы и2 операции: итог131 схем/51 операция/230 независимых сценариев. Из старых128 схем расширена только SolutionCaseChangePreview;127 прежние. В6 прежних preview примерах добавлены эффекты, а два submitted примера намеренно меняют запрет на согласованное разрешение; всего изменены7 прежних сценариев,210 прежних неизменны,13 новых. Legacy project endpoints и модели не менялись. Backend/миграция → frontend; фронтовые port/repository/adapter/use cases и generated types согласованы.

## Приемка этого этапа

| ID | Результат |
| --- | --- |
| ACH01 | Draft и submitted case preview/apply сохраняют точный ввод, scopes и права; обычные writers остаются frozen |
| ACH02 | Все прежние материалы/0/false/состав/дата сдачи и оценки сохранены; только несовместимое неоцененное назначение снято |
