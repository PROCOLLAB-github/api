# BE03 — приглашения в решение

Продолжение C00 1.1.0, согласованного D00 v3 и реализации BE01/BE02. ТЗ: https://chatgpt.com/space/page_9632e9ed74588191b6b3e4b397d55175 . Команда, принятые участники и приглашения принадлежат ProgramSolution; Project и отдельная Team не создаются.

## План и контракт

Реализовать уже определенные C00 операции: список/создание приглашений заявки, входящий список пользователя, безопасное чтение приглашения, PATCH роли/специализации/текста, DELETE pending, accept и decline. Snake_case, строгие поля, пагинация limit/offset/status, существующий Error envelope. Только капитан читает список заявки и отправляет/изменяет/отзывает; только получатель принимает/отклоняет. Безопасное отдельное приглашение доступно капитану и получателю и не раскрывает ответы или чужой состав. Старый /invites/ сохраняется.

Общие блокировки: программа → решение → приглашение. Все изменения повторно проверяют полномочия, включенный режим и ожидаемые версии. Создание/PATCH/accept запрещены после сдачи; decline/revoke остаются доступны для pending. Проверяются регистрация, принятый состав, активная конкурсная exclusivity в legacy и solution, уникальный pending и максимум с резервами. Accept заменяет свой резерв принятым участником, не удваивая численность. Принятое/отклоненное приглашение не меняется повторно; revoke удаляет pending строку. Решение и получатель не переназначаются.

Роль nullable по C00; в интерфейсе обязательна нормализованная строка 1–128 с существующими подсказками. Специализация nullable до 100, текст до 4096. Solution.version повышается при любой успешной мутации приглашения; версия приглашения — при PATCH/accept/decline. Accept возвращает ссылку заявки и новую версию решения; decline — null для обоих полей согласно C00. Снимок сданной работы не изменяется от служебных операций.

Проверки: AC05, AC07–AC09, AC15 в scope приглашений, AC20 и контракты реальных ответов; положительные и отрицательные права, строки/границы/версии, дедупликация, гонки PostgreSQL между решениями и с legacy, read после смены капитана/режима, freeze и сохранение snapshot. Новые правила сроков не вводятся: сохраняется существующая policy команды; дедлайн сдачи применяется отдельной командой BE06.

## Выполненная проверка

Реализованы восемь HTTP-операций приглашений и проверки владельца под блокировками. 17 новых тестов включают два конкурентных сценария PostgreSQL. Совместный прогон основы, команды, приглашений и прежних командных сценариев: 104 проверки PostgreSQL прошли. Black, Flake8 и C00 validator (47 схем, 22 операции, 43 примера) прошли.

Интеграция с Angular на отдельной локальной PostgreSQL: реальный JWT для двух тестовых пользователей, поиск через существующий каталог программы, создание pending, изменение роли, принятие из уведомлений, отзыв, передача капитанства и выход. Проверена мобильная ширина 390 px. Принятие не создает Project и не добавляет участника до согласия.

Совместимое расширение C00 1.1.0 добавляет необязательный permissions.can_leave: сервер явно разрешает собственный выход принятому участнику; капитану, сданной заявке и выключенному режиму возвращается false. Старые клиенты сохраняют совместимость.

Полный локальный PostgreSQL-прогон прерван native access violation процесса Python на Windows в прежних сценариях сертификатов. Успешным его не считаем; полный прогон проверяется Linux CI на соответствующем commit. Новый режим остается выключенным по умолчанию; сдача и редактор ответов относятся к следующим BE04–BE06.
