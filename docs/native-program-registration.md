# Встроенная регистрация в программу

Новый контур включается организатором через «Настройки → Регистрация». Программы без опубликованной конфигурации сохраняют прежние ссылки, JSON-анкету и интеграции. Новые таблицы и snapshot-поля добавляет миграция `partner_programs.0024`; существующие ответы не преобразуются.

Организатор программы (либо действующий администратор по `can_manage_program`) может читать/сохранять `management/registration/` (GET/PUT), публиковать `management/registration/publish/` (POST), предварительно разбирать `management/registration/import/` (POST multipart `file`) и сохранять запрос внешнего подключения `management/registration/connection/` (POST `url`, `comment`). Изменение анкеты требует текущую целочисленную `revision`; конфликт возвращает 409. Импорт не меняет анкету. Статус `connected` может установить только администратор в Django после фактической настройки интеграции; запрос организатора не подключает webhook автоматически.

Черновик: `{mode: native|external, fields: [...]}`. У поля стабильный идентификатор `f` + 32 hex-символа, `label`, `type` (`text`, `textarea`, `number`, `date`, `select`, `multiselect`), `help_text`, `required`, `source` (`own`, `universities`, `regions`), `options`, `allow_other`. Порядок массива определяет порядок анкеты. Свой список — не более 5000 вариантов по 500 символов. Импорт принимает одноколоночный XLSX/CSV UTF-8 до 2 МБ, считает пустые строки и повторы. Пустой список допустим в черновике, но блокирует публикацию.

Публичный `registration/` GET доступен для опубликованной программы с опубликованным native-способом. Ответ включает поля, `version`, `closed`, `authenticated`, `enrolled` и путь программы. POST этого URL записывает только текущего подтверждённого пользователя: `version`, `answers`. Существующее участие возвращается идемпотентно, в том числе после дедлайна. POST `registration/signup/` принимает также имя, фамилию, email, дату рождения, пароль/повтор и согласия `accept_policy`, `accept_age`. Существующая почта требует входа; профиль и пароль существующего аккаунта не меняются. До подтверждения почты создаются только неактивный аккаунт и ожидающая анкета.

Письмо Celery ведёт на `/program-registration/{id}#confirmation=...`: доказательство почты находится во fragment, не в HTTP URL. POST `registration/confirm/` с `token` активирует аккаунт и возвращает JWT в теле ответа, без токенов в redirect URL. Доказательство действует 24 часа и используется один раз. POST `registration/resend/` принимает ограниченную квитанцию `receipt` либо доказательство из письма (до 7 дней); интервал повторной отправки — минимум 60 секунд. После закрытия регистрации подтверждается аккаунт, но новое участие не создаётся. Если анкета изменилась и требуется новый ответ, аккаунт подтверждается, а клиент получает `review_required` и сохранённые ответы для проверки текущей формы.

Новые участники сразу переходят в программу без выбора роли и вводного onboarding. Проверки доступа и глобальная модерация профиля сохраняются; `verification_date` не подставляется. Обычная регистрация и короткая регистрация приглашённых экспертов не изменяются. Восстановление пароля получает `registration_program_id` и возвращает к этой программе.

Ответы хранятся отдельно от профиля и полей проекта. Каждое участие содержит snapshot анкеты: удаление поля из следующих версий архивирует уже полученные ответы. Новые обязательные поля не проверяются повторно для уже зарегистрированных участников. Ответ региона из общего справочника доступен фильтрам участников без изменения глобального профиля. Ответы доступны в списке участников (`registration_answers`) и на листе «Анкеты» отфильтрованной XLSX-выгрузки. Текстовые ячейки экспортируются как строки, без выполнения формул.

Порядок DEV rollout: backend/migration/runtime-права/Celery → Angular. Откат UI не требует удаления таблиц или ответов. Production deployment в эту задачу не входит.
