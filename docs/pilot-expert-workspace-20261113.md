# Программы и единый кабинет эксперта в white label

Выпуск предназначен только для `pilot.procollab.ru`. База переноса — отдельные
ветки пилота после управления чемпионатом: API `aba6fc2`, фронт `5d739ba`.
Контрольная сумма опубликованного HTML подтвердила фронт. Серверная диагностика
владельца подтвердила API по 728 путям, контейнер, состояние, полный интерфейс,
маршруты и отсутствие непримененных миграций. Флаг `PROGRAM_SOLUTIONS_ENABLED`
на пилоте включен; выпуск его не меняет. Следующий DEV PR 868 меняет только
проверку маршрутов DEV и не переносится.

## Источники и границы переноса

- Фронт: PROCOLLAB-github/procollab PR 546, 547, 548; связанные проверки
  организаторов и ручного назначения из PR 545. Применяются существующие UI Kit,
  Mont и токены темы; новое визуальное направление не вводится.
- API: PROCOLLAB-github/api PR 864–867. Изменения DEV CI и скрипт подготовки
  данных DEV в выпуск не входят.
- Сохраняются white label, регистрация, фиксированная светлая тема, веса,
  общий рейтинг и шаблоны писем пилота. Отчеты организатора сохраняют прежнюю
  формулу и определение завершенности; кабинет использует полноту обязательных
  критериев, где комментарий необязателен.
- Квиз, DEV и production не изменяются. Существующие оценки не используются
  для проверки сохранения.

## Проверяемое поведение

1. Опубликованная карточка в «Я организую» ведет на страницу программы.
   Отдельная кнопка «Управлять» ведет в управление. Черновик сохраняет переход
   к настройке; вложенных ссылок нет, клавиатура и мобильный экран поддерживаются.
2. Активный организатор опубликованной конкурсной программы видит ее в
   «Оценивании». Добавление менеджера через API и admin создает техническую
   экспертную запись без смены основной роли и назначения работ. Организаторы
   исключены из автораспределения; ручные назначения проверяют прежние ограничения.
3. Страница программы, виджет, уведомление и старый `projects-rating` открывают
   единое оценивание с нужной программой. Форма использует отдельный маршрут
   `/office/evaluation/:programId/projects/:projectId`, обновляет данные при
   смене работы и возвращается в исходный список с его фильтрами.
   На пилоте эксперт с незаполненным профилем может начать этот путь со страницы
   программы, списка организуемых программ и материалов проекта. Общий онбординг
   не перехватывает эти переходы; профиль и основная роль не изменяются.
4. Ответы анкеты в проекте и оценке принадлежат выбранной программе. Несданная
   работа имеет явную причину блокировки и не оценивается прямым POST. Частичная
   старая оценка остается в ожидающих. Значения 0 и «Нет» сохраняются и после
   перезагрузки попадают в оцененные после заполнения обязательных критериев.
5. Варианты и применение фильтров ограничены выбранной программой. Выгрузка
   следует серверному праву. Архивные приглашения скрыты. Общий кабинет работает
   при выключенном `PROGRAM_SOLUTIONS_ENABLED`, не восстанавливая удаленные
   маршруты и не требуя включения формата «Заявка».
6. Вкладки, карточки, кнопки, поля и пустые состояния используют общие компоненты
   и токены пилота. Проверяются ширины 1440, 390 и 320 px, фокус, длинные названия,
   отсутствие пересечений и сохранение светлой темы.

## Совместимость и выпуск

Применяется добавочная миграция технических записей экспертов из DEV и пустая
миграция слияния с существующей веткой весов и общего рейтинга пилота. Обратная
миграция не удаляет экспертные записи: назначения могут на них ссылаться.
Веса и расчеты общего рейтинга не нормализуются заново.

Перед установкой требуется сверка действующих файлов, флагов, миграций, image,
mounts и настроек. Установщик должен сохранить проверенную резервную копию,
заменять только web и интерфейс пилота и контролировать неизменность остальных
контейнеров, БД, nginx и брендовых настроек. При откате новые оценки не затираются
восстановлением старой БД. Для приемки создается отдельная синтетическая программа
и работы; существующие пользовательские записи и оценки не редактируются.
