# Возможности организатора

Все действия организатора, доступные на фронте, должны дублироваться в Django admin.
Новые и изменяемые действия реализуйте в обоих интерфейсах через общую бизнес-логику
с одинаковыми проверками доступа и сохранности данных. Переход на фронт не заменяет
отсутствующее действие в админке. Все тексты интерфейса организатора и админки
должны быть на русском языке.

# Тексты интерфейса PROCOLLAB

Во всех новых и изменяемых текстах интерфейса используйте Е/е вместо U+0401/U+0451.
Правило относится к подписям, подсказкам, статусам, ошибкам, уведомлениям,
письмам, заголовкам выгрузок, Django admin и макетам Figma.

Не переписывайте пользовательские данные, имена и собственные названия из
справочников. Не меняйте валидаторы допустимых букв, поисковую нормализацию,
идентификаторы и исторические миграции ради этого правила. Проверяйте именно
текст продукта; глобальная подмена символов в данных во время отображения запрещена.

## Code Review Rules

### Действия организатора

- Для нового или измененного действия организатора проверяйте, что API и Django
  admin используют общую бизнес-логику и одинаковые проверки доступа и данных.
  Отмечайте подтвержденные расхождения; если связанный фронтенд недоступен,
  укажите необходимость отдельной проверки, не делая выводов о его реализации.

### Сохранность данных программы

- При изменении регистрации, заявок, проектов, приглашений или оценивания
  проверяйте, что существующие ответы и оценки не теряются и доступ к ним не
  расширяется без предусмотренного правилами роли основания. Изменение схемы
  или действия должно сохранять совместимость с существующими данными.
